# Contributing

Use Node.js 22 LTS and pnpm 10. Follow the README development quickstart, keep changes scoped, and include a clear description of the problem and resulting behavior.

Before a pull request, run `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, and `pnpm build`. Run browser tests when changing the editor or application APIs. Use synthetic credentials and fixtures; never commit `.env`, receipt data, real credentials, or private service URLs.

Shared workflow and tool contracts belong in `packages/contracts`. Schema changes must include a Drizzle migration (`pnpm exec drizzle-kit generate`). Runtime changes should preserve immutable published versions and cover retry, restart, and API-write ambiguity behavior. Provider implementations must implement the adapter interface without exposing credentials to workflow outputs.

Run `pnpm format` to format maintained source and documentation, and `pnpm format:check` before pushing. Generated migration snapshots and the dependency lockfile retain their generator formatting. Tests should verify observable behavior and failure boundaries. Include relevant documentation updates and disclose any checks you could not run. Contributions are licensed under Apache-2.0.

The frontend uses Mantine defaults throughout. Use Mantine components as provided: direct imports, feature composition, and documented props first. Change styling or implementation only for a functional requirement, accessibility, or a demonstrated integration limitation—not visual preference. Use built-in tokens, `md` layout spacing, filled primary actions, default secondary actions, and red destructive actions. Keep default light styling and typography; do not add custom fonts/themes, competing UI libraries, utility styling frameworks, generic control wrappers, vendored internals, or Mantine patches. Scope changes to requested behavior and verified defects.

`pnpm lint` enforces the frontend rules and checks dependencies, stylesheet registration, and exact exception locations. React Flow is the graph integration boundary. Exceptions in `scripts/ui-policy/exceptions.json` identify the exact file/location, rule, source or stylesheet hash, functional reason, and why ordinary Mantine usage is insufficient. Changing the stylesheet requires updating its hash after reviewing the entire small file. No blanket exemptions. Reviewers assess necessity and scope in normal PR review; there is no separate approval step. When changing UI, include browser checks and updated login, builder, dialog, and inspector screenshots.

For the Docker receipt smoke check, start an isolated stack with `docker compose -p ui-smoke -f docker-compose.yml -f docker-compose.smoke.yml up --build -d`, then run `E2E_ADMIN_PASSWORD='<synthetic administrator password>' pnpm test:smoke`. The override uses web port 3001, PostgreSQL port 5439, and separate project volumes. Use an environment created for synthetic local testing. Stop the stack with the same Compose arguments and `down`. CI runs this check and uploads UI screenshots on success as well as failure.

Outcome state IDs are immutable connection keys; names and order are editable. Never append generated instructions to saved system prompts. Report acceptance and the next-node cursor must commit in one transaction before branch execution. Keep task outcome separate from run status, preserve v1 checkpoint decoding and legacy ledger IDs, and keep call scopes isolated by run and node. Test malformed/mixed reports before any action dispatch, interruption on both sides of acceptance, retry/deduplication, and uncertain-write blocking. Tool action references must resolve only earlier outputs on the current path and preserve whole-value JSON types.

Use provider fixture tests for Gemini signatures, OpenAI reasoning items, Claude signed content blocks, call/result IDs, PDF/JPEG/PNG inputs, refusals, truncation, and error classification. Run `pnpm test:live:outcomes` only with the documented opt-in and real provider configuration. Report missing prerequisites and live results separately from mocks. Preserve `pnpm test:live` for the real inbound receipt path. Capture desktop/mobile Outcome editor, settings, and inspector screenshots after UI changes, and rebuild/restart the isolated preview on port 3001 for delivery.
